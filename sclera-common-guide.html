sclera-common — library & configuration

sclera-common is the shared library every Sclera backend service builds on. Add one dependency and your service inherits Keycloak token validation, the standard API response & error format, correlation-id logging, tracing, health checks, and service-to-service call helpers — so your team writes business logic, not plumbing. This guide covers integrating it and configuring a service that uses it.

For the application-plane team Copy-paste ready Includes the config templates
⭐
The one rule to remember: put "com.sclera.controlplane.common" in your @SpringBootApplication(scanBasePackages = { … }). Miss it and the shared beans (error envelope, filters, config) silently never load.
Scope of this pack
  • This share is sclera-common and its configuration only. Fine-grained authorization (@perm, @HasPermission, OpenFGA) lives in a separate module, sclera-authz, and is not part of this hand-off. Services that need permission checks add that module later.

✓What you get

One dependency + one scan package turns on all of this.

Keycloak JWT auth
Validates incoming tokens against the realm keys, maps roles to authorities, and fills the caller's org context.
Standard response envelope
Every response wrapped as {success, data, pagination, error, meta} — consistent across all services.
Central error handling
Extend one base advice and exceptions map to the same error codes and validation format everywhere.
Correlation-id logging
A request id on every log line and response header, colored dev logs, JSON prod logs, OpenTelemetry tracing.
Health & metrics
Actuator liveness/readiness probes, Prometheus metrics, and a Dapr sidecar health check.
Service-to-service calls
HMAC-signed Dapr invocation helper and cached secret-store reads for internal /internal/** traffic.
Config templates
Copy-in application.yml baselines (dev / prod) with a fail-safe default profile and env-var conventions.
Jackson conventions
camelCase fields, ISO-8601 dates, nulls omitted — applied automatically.

⚡Quick start (about 5 minutes)

  1. 1Add the sclera-common dependency + the Spring Security starters.
  2. 2Put "com.sclera.controlplane.common" in @SpringBootApplication(scanBasePackages=…).
  3. 3Add a SecurityConfig: JWT resource server with ScleraJwtConverter, and register MdcFilter + InternalEndpointFilter.
  4. 4Add a @RestControllerAdvice that extends GlobalExceptionHandlerBase (turns on the error envelope).
  5. 5Copy the config templates in and set the JWT jwk-set-uri + your DB/Redis/Keycloak env vars.
  6. 6Run with mvn spring-boot:run.

◈Add the dependency

There is no remote Maven registry — install the jar into your local ~/.m2 once, then reference it.

⚙Configuration

The config/ folder in this pack holds the templates sclera-common ships. Copy them into your service's src/main/resources/ and customize. They are templates, not active config — the library does not put them on your classpath for you.

application.ymlUniversal baseline — servlet, actuator, Jackson conventions, Flyway, async, graceful shutdown. Default profile is dev so an unconfigured environment fails safe to local dev.
application-dev.ymlLocal dev profile — localhost DB/Redis/Keycloak defaults, console logging, Swagger UI on. Boots with almost no env vars.
application-prod.ymlProduction profile — JSON logs, no default credentials (must be injected), stricter settings, Swagger UI off.
logback-spring-template.xmlCopy in as logback-spring.xml. Colored console in dev, JSON in prod, with correlation/trace ids on every line.
logback-spring-defaults.xmlShared per-package log levels, pulled in by the template via <include>. Copy alongside.
Watch out
  • MdcFilter and the logback file are not auto-wired — register the bean and copy the logback template in, or correlation-ids and the X-Correlation-ID header stay blank.
  • Set SCLERA_SERVICE_NAME or the app names itself sclera-unknown-service (pollutes metrics/logs).
  • Default profile is dev — always set SPRING_PROFILES_ACTIVE=prod outside local dev, or you silently run localhost defaults.

🌐Environment URLs (QA example)

Concrete URLs for the QA deployment. QA runs as a single host (qa-app-v2.sclera.com) with a Caddy reverse proxy doing path-based routing: / → frontend, /api/* → API gateway, /auth/* → Keycloak, /actuator/* → gateway. Swap the host for staging/prod (e.g. staging-keycloak.sclera.com).

Internal calls — service-to-service (never public)

/internal/** endpoints are not routed by the reverse proxy. Services reach each other two ways, both guarded by HMAC + InternalEndpointFilter (localhost / private-network source IPs only):

MechanismAddress formExample
Container DNS (direct)http://sclera-<svc>-service:<port>/internal/…http://sclera-identity-service:8083/internal/…
Dapr service invocationhttp://localhost:3500/v1.0/invoke/<app-id>/method/<path>app-id = sclera-identity-service (via DaprInvocationHelper)
How your service makes an internal call
  • Use sclera-common's DaprInvocationHelper.invoke("sclera-identity-service", "api/v1/internal/…", body, Resp.class) — it auto-signs the request with the shared HMAC secret and propagates the correlation id.
  • Both caller and callee must share the same sclera.event-listener.signing-secret, or the callee returns 401 HMAC_FAILED.
  • Expose your own internal endpoints under /internal/** and permitAll() them in SecurityConfig — the HMAC filter + InternalEndpointFilter protect them, not JWT.

⚠Troubleshooting

SymptomLikely causeFix
Shared beans not loading (no envelope, blank logs)Common package not component-scanned.Add "com.sclera.controlplane.common" to scanBasePackages.
Every request returns 401No JWKS configured.Set spring.security.oauth2.resourceserver.jwt.jwk-set-uri.
Errors come back as raw Spring pages, not the envelopeNo @RestControllerAdvice subclass.Add the one-line extends GlobalExceptionHandlerBase class.
Logs / X-Correlation-ID blankMdcFilter not registered or logback not copied.Register MdcFilter + copy logback-spring.xml.
Could not find artifact com.sclera:sclera-commonJar not in local ~/.m2.Run the mvn install:install-file command above.
Readiness probe stuck DOWNDB/Redis/Keycloak unreachable, or Dapr check with no sidecar.Fix connections; set sclera.health.dapr.enabled=false if no sidecar.
Running dev defaults in prodSPRING_PROFILES_ACTIVE unset.Set SPRING_PROFILES_ACTIVE=prod.
